# Architecture

## What belongs here

Code that two or more Apple apps need and that draws nothing: the contract, the tokens, and the engine that
talks to the server. The rule is enforced (`scripts/enforcement`): shared code imports no UI framework, has no
third-party dependency, uses no unchecked concurrency escape and cannot trap on a value it was handed. The rules in full:
[conventions.md](conventions.md).

```
PurlayContract    (no dependencies)
PurlayTokens      (no dependencies)
PurlayKit         -> PurlayContract
PurlayTestSupport -> PurlayKit, PurlayContract
```

| Product | Hand-written | Generated by `Tools/PurlayGen` |
|---|---|---|
| `PurlayContract` | `Primitives.swift` (`Uuid`, `Timestamp`, `JSONValue`) | `Models`, `Endpoints`, `Constants`, `Registry` |
| `PurlayTokens` | `PurlayTokens.swift` (the shapes the values are written in) | every value, from `tokens.json` |
| `PurlayKit` | everything in the folders below | `Generated/PurlayAPI.swift`, the typed API client |
| `PurlayTestSupport` | fakes, `ScriptedTransport` | none |

`PurlayKit` is grouped by concern: `Handshake` (server address, version gate), `Auth` (native sign-in, session cookie, Keychain store),
`Networking` (API client, transport), `Realtime` (connection, cursors, replay, reconnect backoff), `Outbox` (send coordinator, store),
`State` (engine, chat state, windows, navigation, inbox), `App` (`AppModel`, its environment, desktop sessions), `Composer`,
`Markdown`, `Code`, `Attention`, `DeepWork`, `Uploads`, `Palette`, `Diagnostics`.

## What does not

- Views, view models that import SwiftUI, anything platform-specific (Dock badge, login item, APNs registration):
  those live in the apps and reach the Kit through its protocols (`AttentionPresenter`, `WebAuthenticator`, …).
- Feature code for one server module on one platform: that is `purlay-ios`'s `Feature*` packages.

## Platform neutrality

The Kit is a client for one server on several operating systems, so the platform is a value, not a build
assumption: `ClientPlatform` names the client in `X-Purlay-Client`, and every platform-specific act arrives as an
injected dependency in `AppEnvironment`.

## Where the pieces meet

```
purlay (server, owns the contract)  --bundle-->  purlay-swift (pin, generator, Kit)  --version-->  purlay-macos, purlay-ios
```

The pin (`Contract/contract.lock`) names one server release; `scripts/prepare-contract` takes that release's bundle and checks its
digest; `scripts/generate` writes the generated sources; an app pins a release of this package with `from:`.
[The pipeline](../development/contract.md). The consuming apps check that all their own pins agree.

## Other clients

Android does not consume this repository. It generates its own types from the same contract bundle
([decision 0001](../decisions/0001-contract-single-source.md)).
